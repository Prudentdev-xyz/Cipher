================================================================
ROADMAP OVERVIEW
================================================================

CIPHER is being built in 4 major phases across an estimated
16 to 20 weeks from kickoff to Testnet Launch.

  PHASE 0 — Foundation          Week 1  – Week 2
  PHASE 1 — Smart Contracts     Week 3  – Week 7
  PHASE 2 — Frontend            Week 8  – Week 13
  PHASE 3 — Integration & QA    Week 14 – Week 16
  PHASE 4 — Testnet Launch      Week 17+
  PHASE 5 — Mainnet Launch      TBD (Ritual Mainnet dependent)

Each phase has clear milestones. Each milestone has a
definition of done — so there is no ambiguity about when
something is complete and when to move forward.

================================================================

MILESTONE 1.4 — CipherMatch.sol (Core Contract)
Weeks 4 to 5
----------------------------------------------------------------

This is the most complex contract. It gets its own two-week
milestone. All game logic lives here.

Deliverables:
  □ Contract written in Solidity
  □ State variables defined:
      - playerA, playerB addresses
      - stakeMode enum: FREE, TOKEN, PAID
      - stakeAmount
      - playerAStakeConfirmed, playerBStakeConfirmed bools
      - matchState enum:
          PENDING_STAKE, ACTIVE, CONCLUDED, CANCELLED
      - currentRound (1–6, plus tiebreaker)
      - rounds array (RoundData structs)
      - RoundData struct:
          presenter, guesser, category,
          riddle, sketchDescription,
          encryptedSecretWord (TEE reference),
          guess, isCorrect, isClosed
      - scoreA, scoreB
      - winner address
      - matchId

  □ Stake functions:
      - confirmStake() payable — locks tokens in escrow
      - _startMatch() internal — fires when both confirmed
      - cancelMatch() — refunds if stake timeout reached

  □ Round functions:
      - selectCategory(string category) — Presenter calls
        triggers Ritual AI precompile call
      - _generateChallenge(string category) internal
        calls Ritual AI precompile:
          input: category + prompt
          output: riddle + sketchDescription (public)
                  secretWord (TEE encrypted, private)
        registers 30s timer with Ritual Scheduler
      - submitGuess(string guess) — Guesser calls
        stores guess onchain
      - closeRound() — called by Ritual Scheduler at 30s
        decrypts secretWord from TEE
        evaluates guess (case-insensitive string match)
        updates score
        emits RoundClosed event
        calls _startNextRound() or _concludeMatch()

  □ Match conclusion:
      - _concludeMatch() internal
        determines winner by score
        if tie: deploys tiebreaker round
        distributes stake to winner (minus platform fee)
        calls CipherRanking.updateRanking()
        notifies CipherSpectator.resolveMatch()
        emits MatchConcluded event

  □ Ritual AI Precompile integration:
      - Precompile call structured per Ritual docs
      - confidential: true flag set for secretWord
      - secretWord stored in TEE, never in public state
      - riddle and sketchDescription stored in public state

  □ Ritual Autonomous Scheduler integration:
      - 30-second timer registered per round
      - closeRound() registered as the callback
      - Timer fires automatically — no keeper needed

  □ Events emitted:
      - StakeConfirmed(address player, uint amount)
      - MatchStarted(address playerA, address playerB)
      - CategorySelected(uint round, string category)
      - ChallengeGenerated(uint round, string riddle,
                           string sketchDescription)
      - GuessSubmitted(uint round, address guesser)
      - RoundClosed(uint round, string secretWord,
                    string guess, bool correct)
      - MatchConcluded(address winner, uint payout)
      - MatchCancelled(string reason)

  □ Unit tests written and passing:
      - Stake flow (both players, mismatch, timeout)
      - Round flow (category select, challenge gen, guess)
      - Timer close (simulated scheduler callback)
      - Score tracking across 6 rounds
      - Tiebreaker round trigger
      - Winner payout calculation
      - Platform fee deduction
      - CipherRanking.updateRanking() called correctly

  □ Deployed to Ritual Testnet
  □ Contract address noted

Definition of Done:
  A full 6-round match can be simulated end to end
  in tests with correct score tracking, payout, and
  ranking update. Ritual AI precompile call returns
  a challenge. TEE stores secret word invisibly.
  Scheduler fires closeRound() at 30 seconds.

        (matchId => address[] predictors)

        (matchId => address => address)

      - matchPools mapping
        (matchId => uint totalPool)
      - predictionOpen mapping
        (matchId => bool) — closes before final round

  □ Functions implemented:
      - watchMatch(uint matchId) — registers spectator
      - placePrediction(uint matchId, address chosenPlayer)
        payable — locks tokens, stores prediction
        reverts if match is in final round or concluded
      - closePredictions(uint matchId) — called by
        CipherMatch when final round starts
      - resolveMatch(uint matchId, address winner) —
        called by CipherMatch on conclusion
        identifies correct predictors
        calculates proportional share of losing pool
        distributes tokens automatically
        deducts 5% spectator fee to treasury
      - getSpectatorCount(uint matchId) — public view
      - getPredictionPool(uint matchId) — public view

  □ Events emitted:
      - PredictionPlaced(uint matchId, address spectator,
                         address chosenPlayer, uint amount)
      - PredictionsLocked(uint matchId)
      - PredictionResolved(uint matchId, address spectator,
                           uint payout)

  □ Only CipherMatch.sol can call resolveMatch()
      and closePredictions() (access control)
  □ Unit tests written and passing
  □ Deployed to Ritual Testnet
  □ Contract address noted

Definition of Done:
  Spectators can place predictions on live matches.
  Predictions lock when final round begins.
  Correct predictors receive proportional payout
  automatically when match concludes.
  Fee deducted correctly to treasury.
